# Fractalsvelte UI — GPUI edition

Port of `../fractalsvelte-ui` (see its AGENTS.md for the canonical rules) to
[gpuix-fractalsvelte](../gpuix-fractalsvelte), the fork of gpuix-svelte whose stylesheet loader
can turn a plain `.css` file into global rules, `:root` tokens and named `[data-mode]` palettes.

## Rules

- The canonical props, tokens and variant semantics are those of `../fractalsvelte-ui`
  (`src/lib/types.ts` and `src/lib/styles/`). When this package diverges, it diverges
  deliberately and says so in the component's porting comment.
- Styling comes from the stylesheet, not from component code. Components compose canonical class
  strings (variant, size, shape, textsize, spacing, surface utilities) exactly like the DOM
  edition; the sheets live in `src/lib/styles/` and are registered by `components/index.ts` (which
  imports `../styles/index.css`) and by `FractalTheme.svelte`. Do not style components with
  `<style>` blocks or inline styles except for the two things GPUI leaves no alternative for:
  px geometry on the drawn checkbox/switch boxes and progress track, and per-instance colours
  that must read an element-chosen token (Tag's fill).
- `src/lib/styles/theme.css` is GENERATED by `scripts/derive-theme-css.mjs` from the canonical
  oklch tokens. Do not edit by hand; regenerate instead. Every other stylesheet is the canonical
  file vendored verbatim — update it by re-copying from `../fractalsvelte-ui/src/lib/styles/`.
  New flat rules GPUI needs that the canonical sheets express differently go into
  `components-gpui.css` (or `surfaces.css`), each with a comment naming the canonical rule it
  ports.
- Colours always go through `var(--token)`. GPUI cannot parse oklch, color-mix or relative
  colours; the generated theme carries sRGB values with the canonical value as a comment.
- Units are px and rem; GPUI's rem is 16 px, so canonical rem tokens are already correct. `em`
  does not exist: where the canonical library sizes something in em of a text size, the component
  computes px from the type scale (Spinner, Progress, Checkbox, Switch) and says so.
- No `bind:` on text elements — `value` + `onchange`, per the gpuix guide. Checkbox and Switch
  draw their box/track with divs (classes in `components-gpui.css`) and hand state to the caller:
  `checked` + `onchange`.
- `<svg>` takes a `source` string: the icon packs serialize to markup in `Icon.svelte`, which
  hoists each pack's wrapping `g` attributes onto the shapes (GPUI's parser does not resolve
  group inheritance) and sizes through style width/height, not attributes.
- Overlay components are rebuilt on gpuix-fractalsvelte's `Portal`, `Popover`, `Tooltip` and
  `Scroller` primitives, not on DOM fixed positioning.
- Elements: `<button>` is the renderer's alias (role button, tab stop, Enter/Space click,
  disabled semantics). `<span>`, `<label>`, `<a>` and friends do not exist; components use
  `div`/`text`.
- Only GPUI-supported CSS reaches the renderer: no descendant selectors, no `@media`, no
  box-shadow, no transitions, no `%` outside width/height, no `display: none` (use `{#if}`).
- `<svg source>` markup is parsed by GPUI's own svg engine: `currentColor` works (the renderer
  copies the inherited text colour), but `var()` inside the source does not — use literal hex or
  currentColor in svg sources.
- Component props: shorthand `{cols}` sets a prop named by the variable, not by the target's prop
  name. Pass values explicitly (`columns={cols}`) or the target sees its default.
- Anything reading measured geometry (`onlayout`) gets its first report with a later frame; in
  headless runs `await wait()` before trusting it.
- Every component keeps the DOM library's prop names and default values; `shadow` props are
  accepted and ignored, with a comment.

## Validation

`demo/` holds a gpuix-fractalsvelte app that imports the components the way a consumer would.

```bash
node ../gpuix-fractalsvelte/bin/gpuix-fractalsvelte.js demo/main.ts   # a live window
node ../gpuix-fractalsvelte/bin/gpuix-fractalsvelte.js demo/test.ts   # headless checks + demo/shot.png
node ../gpuix-fractalsvelte/bin/gpuix-fractalsvelte.js demo/probe.ts  # mounts each component alone
node ../gpuix-fractalsvelte/bin/gpuix-fractalsvelte.js demo/overlay-probe.ts  # dialog + menu + toasts
```

A component is done when it renders in the headless run with no `dropped unsupported style`,
`zero size` or `not defined` warnings of its own and appears correctly in `demo/shot.png`.

`node_modules/gpuix-fractalsvelte` is a symlink to `../gpuix-fractalsvelte`.
